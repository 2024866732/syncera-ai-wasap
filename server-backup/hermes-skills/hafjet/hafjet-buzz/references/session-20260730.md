# Session 2026-07-30: Buzz Debugging Insights

## Community Host Multi-Entry Problem

Buzz creates a new community entry in Postgres every time the relay restarts with a different `BUZZ_DOMAIN`. Result: 3+ community rows with different hosts.

**FK constraint prevents DELETE:** `events` and `relay_members` reference community IDs.

**Working fix:** Update ONLY the main community (the one with events) to the target host. Leave orphan entries (0 events).

```bash
docker exec buzz-prod-postgres-1 psql -U buzz -d buzz \
  -c "SELECT c.host, COUNT(e.id) AS events FROM communities c LEFT JOIN events e ON c.id = e.community_id GROUP BY c.host;"

docker exec buzz-prod-postgres-1 psql -U buzz -d buzz \
  -c "UPDATE communities SET host = '100.121.94.41:3000' WHERE host = 'buzz.example.com';"
```

## Nostr Key Generation: openssl ecparam = BROKEN

`openssl ecparam -name secp256k1 -genkey` produces invalid Nostr keys:
- Public key extraction gives wrong-length hex
- `BUZZ_RELAY_PRIVATE_KEY` is rejected: "Invalid secret key"

**Working method:** `uv run --with coincurve python3`

## sed CHANGE_ME Trap

`sed "s/CHANGE_ME/$(openssl rand -hex 32)/g"` replaces ALL CHANGE_ME fields with SAME hex — including `BUZZ_RELAY_PRIVATE_KEY` and `RELAY_OWNER_PUBKEY` which need valid secp256k1 keypairs, not random hex.
